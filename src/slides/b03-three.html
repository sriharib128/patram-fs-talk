At ten million files, three things go wrong, and they are three different problems.

First, the shared filesystem. It keeps a metadata entry for every file, and it slows down with the number of files, whatever their size. At ten million files, just listing the dataset folder takes minutes. Worse, this is shared: the metadata load slows every other machine and every other team on the cluster.

So move the data to the object store. It has plenty of room, but it limits requests, not bytes. S3 allows roughly 5,500 requests per second for each prefix. A run that fetches samples one at a time makes about ten million requests against that limit. Small files are the worst case, because you pay for one request per file however few bytes it holds.

The third one is easy to miss. A machine runs several processes that read the same data: training, a data job, someone's notebook. They know nothing about each other, so each one fetches its own copy. That wastes the network, the disk and the memory.

Patram-FS solves these in order. Too many files is the first one, and that takes us to shards.
