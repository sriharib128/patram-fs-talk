Deleting a shard that is being read

Process A is in the middle of shard 3. The shard is now the least recently asked for, and the daemon deletes it.

What happens to Process A?
AIts next read fails.
BThe daemon waits until it closes the file.
CIt finishes normally.
Linux removes the name at once. The data stays until the last process with the file open closes it.
Source: Patram-FS engineering post

Here is a shard on the disk. A file on Linux is really two things: a name in a folder, and the data the name points to. Process A has this shard open and is in the middle of reading it. Now the budget goes over its mark, and this shard is the least recently asked for, so the daemon deletes it.

What happens to process A? Does its next read fail? Does the daemon have to wait until it is done, which would mean tracking every reader? Or does it finish normally? Take a guess.

It finishes normally, and the daemon does not have to track anyone. On Linux, deleting a file removes its name at once, but its data stays until the last process that has it open closes it. So a process in the middle of a shard carries on. A process that opens the shard afterwards finds it missing, gets FileNotFoundError, and asks the daemon again. That is simply the normal path for any missing shard. We did not need to build anything for this case: it is the same miss path you saw earlier.
