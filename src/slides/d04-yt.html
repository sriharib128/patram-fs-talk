Where shard bytes travel on one machine

Should the daemon read the file and pass the bytes to each process?
AYes. Every read goes through the daemon.
BNo. The daemon gives the location, and the process reads the file itself.

Source: Patram-FS engineering post

Here are the pieces on one machine so far. Three processes, the socket, the daemon, the local drive, and the object store outside. The dashed lines are questions: ensure_shard, once per shard. The orange line is the download. I have left something out on purpose: how do the bytes get from the drive to the process?

Every process already talks to the daemon, so the tempting design is to route everything through it. The daemon reads the file and passes the bytes along, like a small server. The other option is that the daemon only says where the file is, and the process reads it directly. Which would you choose? Remember the ratio: millions of reads, and one question per shard.

We chose B, and the green line shows it. The daemon never handles the data. It answers "is this shard on the local disk, and where?", and the process reads the bytes on its own. Two things follow. The daemon cannot become a bandwidth bottleneck, because no data passes through it. And restarting it cannot break a read in progress, because each reader holds its own open file.

There is also a bonus to having one daemon per machine: every machine-wide question has one place to be answered. How hard are we hitting the object store, what is cached, how many bytes were downloaded today? Each daemon publishes those as Prometheus metrics, so the whole cluster reads as one Grafana dashboard.
