Problem 1 · Shared filesystem

More files means a slower shared filesystem

Every file needs its own lookup before its first byte, however small the file is.

At ten million filesListing the dataset folder takes minutes
And it is sharedThe load slows every other machine on the cluster
Illustrative: the drawing uses 40 files, and timing is simulated.

Let us try the shared filesystem. Before it can give you a single byte of a file, a filesystem has to look that file up: its name, its size, and where its bytes are. That bookkeeping is called metadata, and the filesystem keeps one entry for every file. Picture a clerk in the records room who has to find the right card before handing over any file.

On the left is some data stored as one big file: one lookup, and then the bytes flow. On the right is the same data stored as many small files. Every one of them needs its own lookup. Watch the counter. The disks are not the slow part here. The clerk is.

Now scale that to ten million files. The cost grows with the number of files, whatever their size. Just listing the dataset folder takes minutes. And the part people forget: this filesystem is shared. Our readers keep the clerk busy, so every other machine on the cluster slows down too.
